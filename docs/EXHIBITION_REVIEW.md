# 2026 年工博会现场展示与工程复盘

[返回项目首页](../README.md) · [系统总体架构](ARCHITECTURE.md)

## 背景与证据范围

本项目作为上海电力大学大学生创新创业训练计划（大创）项目代表，在 **2026 年中国国际工业博览会（工博会）**进行现场展示。本复盘依据项目成员提供的现场经历，保留展示失败、采取的措施及未确定的问题，不补造测试数据、硬件参数或算法指标。

现场整机系统、实验室原控制链路与当前公开的 InspectionBrain 离线原型不能等同。当前仓库没有提供完整现场通信日志、控制程序、网络测量或干扰测试报告，以下区分观察事实、解释假设与后续验证方向。

## 1. 语音交互与电力领域语义理解

### 设计目标与实验室表现

项目原本设计的链路为：麦克风采集 → ASR 转写 → 电力术语词库处理 → 专业术语、同音错字、口误和复杂表达纠错 → 结合千问模型处理复杂语义 → 分发至对应 Skill。继电保护装置、配电设备、高压套管等领域术语相对集中，因此尝试通过词库与大模型结合降低通用语音识别在专业场景中的理解偏差。

这是原设计目标，不表示整条链路已经在当前公开仓库完成集成。现有代码保留原文、输出保守纠错候选和不可执行草案；Qwen3 4B 的 Ollama 命令行测试也不能替代 v3 集成验收。

据现场回顾，实验室内语音前进、后退、左转、右转及瞬时速度、角速度反馈可以运行。该经历属于当时整机系统，不证明当前语义草案具备运动执行能力。

### 现场问题与处理

展厅复杂无线网络环境下，语音控制链路无法稳定工作；线上平台连接不稳定，识别和转换后的文本也无法正常展示。团队启用手持遥控器作为备用控制方式。

不能将展示失败直接写成 SenseVoice 准确率低：

| 环节 | 已知情况 | 尚需证据 |
|---|---|---|
| 语音采集 | 原设计使用麦克风 | 现场录音质量、噪声、采样配置 |
| ASR | 项目有本地识别实验 | 同段音频的原始转写与人工参考，不能由网络中断推断错误率 |
| 网络传输 | 通信与平台访问不稳定 | 请求时间线、失败和延迟分布 |
| 平台展示 | 无法稳定显示识别转换文本 | 服务端响应、页面接收与渲染日志 |
| 控制分发 | 语音控制受到影响 | 当时分发和底层状态，不以新原型代替现场证据 |

后续方向是本地优先的采集、识别与语义处理，以及分环节状态和证据记录；这些不是已经完成的可靠性改造。

## 2. 复杂无线环境下的网络通信

工博会展厅存在大量无线设备和信号。现场出现机器人与上位机通信不稳定、连接频繁中断、线上平台访问不稳定及控制链路受延迟影响；极端情况下存在机器人失去正常控制的风险。

团队重新启用手持遥控器，由人工控制运动。不能仅凭这些观察确定具体频段拥塞、干扰源或协议缺陷，也不能推定遥控器通道完全独立或已具有经验证的冗余能力。

**实验室局域网运行稳定，不代表大型展厅环境下也能稳定运行。** 后续应调查网络拓扑、链路依赖和服务位置，设计独立局域网、网络质量监测、通信超时与重连、本地离线语音和本地语义、手动接管机制，并在断连和高延迟条件下验证。网络恢复不应被直接视为恢复运动授权。

## 3. 机器人运动安全约束

为应对通信不稳定与现场运动风险，项目在硬件底层设置了：

1. 通信延迟超过安全阈值时停车保护。
2. 底盘运动速度限制。
3. 转弯时轮组旋转角度限制。
4. 降低过快运动导致上方设备或载荷掉落的风险。
5. 通信异常时优先保证人员和设备安全。

**通信延迟超过底层配置的安全阈值时触发停车保护，具体阈值以实际控制程序和配置为准。** 现场口述曾涉及约 200ms 或 500ms，数值尚未确定，不能选择其中之一作为已验证参数。速度、角度、载荷等参数也待补充，不将具体底盘机构作额外推定。

这些是项目成员说明的底层措施，仓库中没有完整控制程序可独立核验。当前 Brain 的 SafetyGuard 只封装不可执行语义，不实现上述停车控制。后续需要核对实际配置，验证通信异常、停车、人工接管和恢复行为；软件监督不能替代底层保护。

机器人系统不能只追求运动控制的灵敏度，还必须考虑通信异常情况下的失效安全。

## 4. 自动建图与现场功能保留

语音交互和线上平台受到影响时，现场仍展示了：

- 机器人移动过程中的自动建图。
- 双摄像头相关视觉展示。
- 部分巡检记录展示。

团队保留了这些可用功能，说明并非所有机器人功能都依赖线上语音平台，也不应把语音链路失败描述成整机全部功能失效。

具体建图使用的传感器与算法以实际实现为准。已知硬件包括 RS16，但没有足够资料将建图算法、传感器组合、定位精度或视觉识别效果写成确定结论。部分巡检记录展示的来源、是否模拟及保存流程仍待补充，不能据此认定已接入真实巡检数据库。后续应验证各展示链路的独立性、多传感器稳定性与数据来源标识。

## 5. 电梯环境中的红外干扰

机器人进入电梯后，现场出现红外干扰现象，电梯门无法正常关闭。这是独立的环境兼容性问题，需要保留，不将其归入一般无线网络故障。

电梯门红外光幕与机器人红外设备可能存在兼容性问题，**具体干扰机理尚未确定**。当前无法据此锁定是哪一台机器人设备，也不能将 RS16、双摄像头或海康设备直接判定为干扰源。

现场措施为记录问题；尚无已验证的修复方案。后续应在获准且受控的电梯测试条件下调查干扰源、发射频率、安装位置及工作方式，进行分设备对照与兼容性测试，记录现象是否可复现。未完成验证前，不宣称已确定原因或已解决，也不提出屏蔽电梯安全装置的做法。

## 问题总结

| 问题 | 现场表现 | 已采取措施 | 后续方向 |
|---|---|---|---|
| 语音交互 | 语音链路无法稳定展示，文本展示受影响 | 使用遥控器备用 | 本地化语音链路、分环节观测 |
| 无线网络 | 通信中断、平台访问不稳定 | 人工接管 | 网络冗余与离线运行，质量监测及超时重连 |
| 运动安全 | 通信延迟带来失控与载荷风险 | 底层停车保护、速度与转向限制 | 完善独立安全监督，核实配置并验证异常行为 |
| 环境建图 | 自动建图及部分功能正常 | 保留自动建图、视觉与部分记录展示 | 提高多传感器稳定性，确认算法与数据来源 |
| 电梯红外干扰 | 电梯门无法正常关闭 | 记录现场问题 | 干扰源排查与红外兼容性测试 |

## 后续证据与工程重点

优先补充实际硬件型号、设备拓扑、底层停车阈值与限幅配置、现场音频和链路日志、建图算法及传感器组合、巡检记录来源、电梯干扰复现记录。没有资料的项目保持“待补充”，不回填估计数据。

工博会经历使项目从实验室功能验证进一步转向真实环境下的工程可靠性问题。未来重点是离线自治、网络通信可靠性、任务执行容错、安全控制和多传感器环境兼容性。对应建设阶段见[总体架构路线](ARCHITECTURE.md#7-分阶段建设与验证目标)；这些是后续工作，本次仅完成文档整理。
