# ADR 0001：单机事务事件与 Mock 执行边界

状态：本版本采用。

## 背景

项目需要可测试的任务生命周期、弱网恢复与可观测性，但真实硬件和业务系统尚未接入。现有 Brain 已有封闭语义合同，不宜为任务调度重写。

## 决策

1. 复用 Brain 原 Schema / Evidence / Validator / Guard，新增 Ollama 原生 format=Schema Provider；通过独立适配层重新验证并映射 Mock ID。
2. 使用标准库 SQLite、单 Worker、优先级 FIFO。状态、事件、Outbox 同事务，文件锁串行 Worker 与恢复。暂不引入 Redis、分布式队列或多 Worker 租约。
3. 使用可终止 Linux 子进程执行 Skill，避免超时线程继续产生结果；本地插件仍是可信代码，不声称安全沙箱。
4. 投递至少一次，用稳定事件 ID 和模拟远端主键去重。任务幂等键不保证任意外部副作用 Exactly-once。
5. 不确定的非幂等结果必须人工复核；高风险模拟任务需要独立凭据审批；运动和非 Mock scope 永远拒绝。
6. 关键事件直接持久化；可批量证据使用显式背压，内存缓存不承诺断电保存。审计不默认清理。

## 代价与后续

单机写吞吐、Linux 平台依赖、SQLite 磁盘容量和显式恢复是当前限制。跨 Skill DAG、真实模型效果、Xavier 部署、外部授权服务、身份台账、真实云端接收和硬件执行均需独立设计与验收。选择透明拒绝歧义，不用静默补全扩大能力声明。
