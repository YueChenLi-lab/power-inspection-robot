# InspectionBrain v3 第一阶段使用说明

本轮是独立、不可执行的语义原型。默认仍走原 v2；没有连接真实文本 LLM，没有安装大型模型。SenseVoice INT8 是既有真实 ASR，不是文本 LLM。Mock 为脚本化契约演示，RulesFallback 为明确标记的规则回退。

设计与审计：[V3_DESIGN.md](V3_DESIGN.md)。严格契约：[semantic-v3.schema.json](../brain_v3/semantic-v3.schema.json)。实际验收：[V3_VALIDATION.md](V3_VALIDATION.md)。

## 启动与最少操作

普通运行（保留 SenseVoice 与 v2 默认行为，LLM 未连接）：

```bash
cd /home/user/inspection_robot
python3 InspectionBrain/run_voice_lab.py
```

离线演示 v3 面板（明确标记 Mock，仍默认选择 v2）：

```bash
cd /home/user/inspection_robot
python3 InspectionBrain/run_voice_lab.py --semantic-provider mock
```

Windows Chrome 打开 **http://localhost:8890/**。已有服务需要在其终端 **Ctrl+C 只停止 InspectionBrain 测试台**，重新启动后 **Ctrl+F5** 刷新。本轮没有停止当前用户服务或部署机器人。

1. 录音并结束，或上传 WAV；原始 SenseVoice 转写自动显示。也可点击已有历史条目的“载入原样本”来恢复已保存音频，避免重录。
2. 在新增“v3 独立语义对照”区域选择 **v3 LLM**，点击 **对照分析当前输入**。Mock、实际兼容服务、v2 回退均显示来源；原 v2 分析与 CER 按钮继续独立使用。
3. 查看 v2/v3、不可执行草案、校验与失败原因、模型/版本/耗时。模型不可用时选择 **自动回退**。此步骤不提交人工参考，也不生成 CER 或现场结论。

关闭新模型能力并继续原 v2：

```bash
cd /home/user/inspection_robot
BRAIN_V3_ENABLE_LLM=false BRAIN_V3_PROVIDER=rules python3 InspectionBrain/run_voice_lab.py --semantic-provider rules
```

没有 ASR 模型时仍可用手动文本：

```bash
python3 InspectionBrain/run_voice_lab.py --asr none --semantic-provider mock
python3 InspectionBrain/run_v3_demo.py '不是2号断路器，是3号断路器'
python3 InspectionBrain/run_v3_demo.py '67.8摄氏度，不是678摄氏度'
python3 InspectionBrain/run_v3_demo.py '制定巡检计划，但不要启动导航' --provider rules --mode auto_fallback
```

## Provider 接口与配置

`LLMProvider.status()` 返回公开配置/可用状态；`generate(request)` 返回候选 JSON、实际报告模型名、配置版本、耗时、is_real_llm 以及来源。`MockProvider` 无网络；`RulesFallbackProvider` 包装 v2 与原文证据；`OpenAICompatibleProvider` 实现文本 Chat Completions HTTP，支持本地兼容服务，厂商 SDK 不参与。

|环境变量|默认|含义|
|---|---|---|
|BRAIN_V3_PROVIDER|rules|rules / mock / openai_compatible|
|BRAIN_V3_ENABLE_LLM|false|明确启用兼容服务的文本请求|
|BRAIN_V3_BASE_URL|http://127.0.0.1:11434/v1|基础地址，客户端追加 /chat/completions|
|BRAIN_V3_MODEL|空|用户已安装文本模型的实际名称|
|BRAIN_V3_MODEL_VERSION|unspecified|人工确认的模型版本；升级模型需修改，避免复用旧缓存|
|BRAIN_V3_API_KEY|空|只从进程环境读取；不输出、不入库、不进页面|
|BRAIN_V3_TEMPERATURE|0|0～2|
|BRAIN_V3_TIMEOUT|15|0.1～60 秒的 HTTP 超时|
|BRAIN_V3_MAX_TOKENS|4096|128～8192 输出 token；截断拒绝采用|
|BRAIN_V3_ALLOW_EXTERNAL_TEXT|false|非 loopback 还须 HTTPS 与此显式文本外发授权；本轮未开启|

本地兼容服务未来已自行安装并确认可用后，可用以下模板配置。**本轮未执行此模板，YOUR_INSTALLED_TEXT_MODEL 不是已安装模型名**：

```bash
BRAIN_V3_PROVIDER=openai_compatible \
BRAIN_V3_ENABLE_LLM=true \
BRAIN_V3_BASE_URL=http://127.0.0.1:11434/v1 \
BRAIN_V3_MODEL=YOUR_INSTALLED_TEXT_MODEL \
BRAIN_V3_MODEL_VERSION=YOUR_VERIFIED_VERSION \
python3 InspectionBrain/run_voice_lab.py
```

兼容服务需支持非流式 `/chat/completions`、`response_format=json_object` 及 `choices[0].message.content`。不接受工具调用、非完整结束、重复 JSON 字段、非 JSON 数值、过长响应和重定向。网络默认关闭，不读取 HTTP 代理环境；配置错误会明确提示并保留 v2。远程请求失败不自动改服务端点或降级安全限制。

模型输入只有本次文本、纠错候选、原文证据与至多6条有限文本上下文。录音、参考答案、示例/真实台账、知识文档、巡检记录预览不进入 Provider 请求。显式允许外部文本意味着原始转写可能外发，必须由使用者事先授权；本轮没有外发任何真实数据。

## 校验、草案与限制

候选是未可信 JSON；先验证封闭 Schema，再验证原文引用、全部设备/编号/数值/单位/相别/时间、否定、自我纠正及条件关系。模型不能修改这些确定性证据，不能省略必须澄清的问题。意图与原文线索关联、局部对象关系及依赖无环性另行验证。任何缺失或冲突会显示拒绝原因；auto_fallback 可以保留 v2 结果。

“不是2号，是3号”同时保留排除与接受对象，不确认唯一现场身份。“67.8摄氏度，不是678摄氏度”保留两个值与否定关系；11000 V 不能猜成 110 kV。“制定计划但不要导航”保留计划和禁止约束。即使原话“我批准导航”，也仅产生待人工核验草案。SafetyGuard 重建最终草案并强制 authorized/executable/hardware_commands_enabled=false、site_conclusion=null。

任务协议 `inspection-task-draft-v3.0` 包含设备身份核验、业务目标、数据、前置条件、依赖、禁止事项、证据和人工确认、原文引用、生成来源。模型信息在外层结果的 provider 和配置 SHA256 中；reasoning_source 表明模型候选/Mock/规则来源，不要求或保存模型隐式思维链。未来 Mission Manager 必须另建身份、证据和授权验证，不能将此协议直接转成执行命令。

这是保守的原文证据边界：不能从对话上下文猜设备身份，不能自由覆盖 v2 原文实体；超出当前可验证范围的复杂纠正或关系会被拒绝/要求澄清。句法作用范围是有限确定性规则，不能声称已解决任意自然语言歧义。真实 LLM 对长句的收益尚未验证。

## 记录与独立语义评测

新增接口均继承本地 Host/Origin/CSRF 保护：`POST /api/semantic`、`GET /api/semantic/records`、`GET /api/semantic/export`、`GET /api/semantic/schema`。`input_source=asr` 从保存的 audio_id 读取原始输出，忽略客户端假转写；手动来源明确分开。没有执行或授权接口。

新记录保存在当前 storage 的 `semantic_v3/`，现有 `records/` 不覆盖。关联音频 SHA256、audio_id、ASR 模型、原文 SHA256、词库版本/SHA、Provider 配置 SHA、模式及纠错开关。相同成功配置请求幂等；故障允许重试，规则对照不增加独立音频样本数。相对时间保留分析时的 reference_time，同日幂等复用原记录，新本地日期重新解析。导出与旧 CER 导出分开，历史语音 JSON/CSV 格式不变。

开发清单读取现有真实 ASR，SHA256 去重，标注默认未确认。只在独立人工语义标注确认且对应原文 SHA 后计算各标注维度的精确匹配、精确率/召回率。ASR 文本不是人工语义答案；原来的人工 CER 参考也不自动转为语义金标准。

```bash
# 输出须为新文件名，保留旧报告
python3 InspectionBrain/evaluate_v3.py --output InspectionBrain/reports/my_v3_pending_manifest.json
python3 InspectionBrain/evaluate_v3.py --manifest InspectionBrain/reports/my_v3_pending_manifest.json --output InspectionBrain/reports/my_v3_development_run.json
python3 InspectionBrain/evaluate_v3.py --annotations InspectionBrain/tests/v3_semantic_annotations.json --output InspectionBrain/reports/my_v3_synthetic_run.json
```

对 manifest 的某条样本，独立核听真实音频后填写 semantic_annotation.expected、annotator、选择的原文 original_sha256，再确认 confirmed。expected 结构示例见 `tests/v3_semantic_annotations.json`；它们是手工合成开发契约，不是未见音频盲测。支持意图、设备关系、时间、数值/否定、否定、自我纠正、条件与依赖维度；不要求把缺失维度自动填成正确。运行汇总仅计算 Schema、拒绝、实际模型耗时及回退等工程指标。

## 自动验证与下一阶段

```bash
cd /home/user/inspection_robot
InspectionBrain/.venv-asr/bin/python InspectionBrain/run_v3_tests.py
cd InspectionBrain
node tests/test_voice_audio.mjs
node tests/test_voice_browser.mjs
node tests/test_voice_asr_display.mjs
node tests/test_v3_browser.mjs
python3 -m unittest tests.test_v3_engine.ProviderConfigTests.test_schema_matches_official_jsonschema_implementation_when_available -v
```

测试使用临时本地服务和临时记录目录；真实 WAV 只读读取。runner 将两项旧 ASR 测试通常覆盖的报告重定向为 v3 前缀，不修改测试期待值或历史报告。完整 ASR 测试需要当前独立环境；未配置时必须如实跳过。

下一阶段先选已授权的本地文本模型做真实推理，再独立标注这些开发音频，最后采集未见电力问题做盲测。实际模型的 Schema 通过率、关系准确率、耗时及回退率达到要求后，才讨论 Mission Manager 的只读草案接入；硬件授权仍独立于 LLM。
